# GPU parity fixtures

Golden CPU fixtures for the DALI-preprocess and CUDA-postprocess parity gate
(`tests/unit/test_gpu_parity.cpp`). Every file here is derived deterministically
from a source image or a fixed-RNG synthetic tensor, so a stale fixture can be
regenerated rather than guessed at.

## Regeneration

The generator is a CPU-only dev tool compiled with the default build:

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --target gpu_parity_gen
./build/gpu_parity_gen tests/data/gpu_parity
```

It writes, per natural fixture, `name.jpg`, `name.preprocessed.bin`,
`name.outputs.bin`, `name.expected.txt`, plus `dense.outputs.bin` and
`dense.expected.txt`.

## Fixture set

Resolution is **432** for every stored tensor — the only resolution with a
checked-in `.dali` pipeline, keeping the committed binary bulk to one set.

| Fixture | Geometry | What it catches |
|---------|----------|-----------------|
| `small` | 256×192 | upscale on both axes |
| `wide`  | 1024×288 | independent `scale_x`; a letterbox shift is horizontal |
| `tall`  | 288×1024 | independent `scale_y`; the downscale path (`antialias=False`) |
| `dense` | synthetic | > 100 above-threshold detections — a truncating postprocessor |

Images are generated by `make_test_image` (`tests/unit/gpu_parity_fixtures.hpp`):
smooth gradients plus two Gaussian blobs, seeded per fixture (`small` seed 10,
`wide` seed 11, `tall` seed 12). They are saved as JPEG because the DALI
`EncodedImage` pipeline decodes with nvJPEG, which reads only JPEG.

Synthetic model outputs follow `make_synthetic_outputs`: the natural fixtures
use 12 queries, 4 classes, 32×32 masks, 8 above-threshold hits (seeds 100/101/102);
the dense fixture uses 300 queries, 9 classes, 32×32 masks, 200 hits, seed 99,
decoded against a 640×480 frame.

## File formats

- `name.preprocessed.bin` — raw float32 `[1, 3, 432, 432]`, the CPU tensor from
  `preprocess_bgr_image` on the decoded JPEG.
- `name.outputs.bin` — four int32 header fields (`num_queries`, `num_classes`,
  `mask_h`, `mask_w`) then raw float32 `dets`, `labels`, `masks`.
- `name.expected.txt` — text: `orig_w`, `orig_h`, `count`, then one
  `class_id score x_min y_min x_max y_max` line per detection.

## Size

Total committed size is ~8.6 MB. The three `*.preprocessed.bin` files dominate
(~2.24 MB each at 432); the images are ~70 KB combined and the synthetic-output
files ~1.3 MB. This is the bound the phase accepted: tensors are stored for one
resolution only, and the synthetic outputs use the smallest masks that still
exercise the decode.

## Measured parity (RTX 3060, 2026-09-08)

- **Resize + normalise parity** (`GpuParityPreprocess.ResizeMatchesCpu`, frame
  path): max `|Δ|` = **0.0088** on all three natural fixtures — within the
  `2e-2` tolerance.
- **Encoded-path parity** (`GpuParityPreprocess.EncodedPathBounded`): max `|Δ|`
  = 0.050–0.069. The gap is entirely the JPEG decode: nvJPEG and stb are
  different decoders, so the encoded tensor cannot bit-match the CPU tensor.
  The frame-path result above isolates resize and shows it is not the source.
  This is the "DALI preprocessing parity remains open" item in the CHANGELOG.
- **No letterbox** passes on `wide` and `tall`.
- **End-to-end regression** passes on all four fixtures (detection set: class,
  count, score `1e-3`, box centre 1 px); `dense` yields 200 detections.

## CPU baseline numbers (measured with `./build-gpu-bench/benchmarks`)

Recorded so Phase 4's numbers have a reference; "infer" is engine-bound and is
measured on the Phase 4 exit gate, not here.

| Stage | CPU | GPU |
|-------|-----|-----|
| Preprocess 432 | 7.06 ms | 4.58 ms (DALI) |
| Preprocess 560 | 11.7 ms | — (no 560 `.dali` pipeline) |
| Preprocess 576 | — | 4.68 ms (DALI) |
| Transfer (3.7 MB H2D+D2H) | — | 1.75 ms |
| Seg postprocess, 1080p source, ~120 detections | 3553 ms | 541 ms |

The 1080p segmentation number is the whole point of the CUDA postprocessor: the
mask resize dominates, and the GPU path is ~6.6× faster.
